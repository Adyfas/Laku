## Tujuan

Memperbaiki tujuh cacat pada laporan tanpa menghapus data resep/draft secara diam-diam, menyelaraskan HPP dengan inventory, dan menjaga kompatibilitas dengan Produksi.

Batas modul:

- HPP membaca inventory dan menyimpan resep sebagai rencana biaya.
- HPP tidak mengurangi stok.
- Produksi tetap menjadi satu-satunya modul yang mengurangi stok setelah konfirmasi produksi.
- Referensi inventory yang hilang dipertahankan, diberi peringatan, dan dapat diganti atau dihapus secara eksplisit.

## Keputusan Desain

1. **Inventory hilang tidak dihapus otomatis.** Kartu bahan tetap muncul dengan peringatan. User dapat:
   - mengganti bahan dengan inventory yang masih ada;
   - menghapus bahan secara eksplisit;
   - melanjutkan edit resep tanpa kehilangan draft.
2. **Perhitungan HPP tetap memakai snapshot terakhir** (`nama`, `hargaBeli`, `jumlahPakai`, dan satuan) untuk bahan yang inventory-nya hilang, tetapi UI harus menandainya sebagai unresolved. Resep tetap dapat disimpan sebagai rencana; Produksi akan melaporkan shortage saat inventory tetap tidak tersedia.
3. **Edit berpindah dengan save-first.** Jika draft edit bahan/overhead berubah, simpan jika valid; jika tidak valid, tampilkan error dan tetap pada edit lama. Jangan menimpa `editingId` atau draft sebelum keputusan selesai.
4. **Reset setelah simpan berhasil adalah auto-clear tanpa konfirmasi.** Reset tidak me-reload halaman dan tidak menghapus resep yang baru tersimpan. Aksi reset manual, jika kelak ditambahkan ke UI, harus memakai jalur terpisah dengan konfirmasi destruktif.
5. **Jumlah produksi boleh desimal.** HPP tidak memakai `parseInt()` untuk jumlah produksi. UI Produksi harus menerima desimal karena mesin Produksi sudah memakai `Number(quantity)`.
6. **Margin maksimum diselaraskan ke 99%.** Margin 100% membuat penyebut harga jual nol. Slider dan engine harus menunjukkan batas yang sama, tanpa silent clamp dari 100% ke 99%.
7. **ID HPP memakai generator terpusat.** Inventory tetap memakai ID milik modul Inventory. Semua lookup lintas modul memakai perbandingan `String(id)` agar resep numerik lama tetap kompatibel.
8. **Semua input numerik harus finite.** Nilai `NaN`, `Infinity`, negatif pada field yang wajib positif, dan nilai di luar batas harus ditolak dengan pesan spesifik, bukan diubah diam-diam menjadi nol.

## Tugas Implementasi

### 1. Kontrak ID, numerik, dan HTML

- Tambahkan helper di `javascript/apps/hpp/hppClient.js` dan expose melalui `window.LakuHpp`:
  - generator ID terpusat dengan prefix `ing_`, `ovh_`, dan `rec_`;
  - parser numerik yang hanya menerima `Number.isFinite()`;
  - comparator ID berbasis `String()`;
  - escape HTML untuk nama dan teks dinamis.
- Ganti semua pembuatan ID internal HPP dengan helper tersebut.
- Jangan ubah ID inventory yang sudah tersimpan.
- Ganti seluruh `parseInt()`/`parseFloat()` pada ID dengan nilai string asli.
- Gunakan helper numerik pada HPP dan validasi Produksi; jangan mengubah format mata uang integer yang sudah ditangani `getRawNumber()`.

### 2. Session dan migrasi data

- Naikkan `HPP_SESSION_VERSION` dari 3 ke 4.
- Tambahkan migrasi v2/v3 ke v4 yang:
  - menormalkan array bahan dan overhead;
  - memberi ID internal hanya jika hilang;
  - menormalkan nilai numerik tanpa mengubah snapshot yang masih valid;
  - mempertahankan `inventoryId` yang tidak lagi ditemukan;
  - menghapus hanya state edit inline jika target item tidak ada, bukan item/draft resep.
- Normalisasi resep lama di `loadRecipes()` tanpa menghapus field yang tidak dikenali.
- Pertahankan kompatibilitas resep ber-ID numerik melalui perbandingan `String()`.

### 3. State edit dan event delegation

- Implementasikan transisi edit async untuk bahan dan overhead:
  - bandingkan draft ternormalisasi dengan item tersimpan;
  - jika tidak berubah, lanjutkan;
  - jika berubah dan valid, simpan sebelum membuka edit baru;
  - jika berubah tetapi invalid, tampilkan error dan pertahankan edit lama.
- Terapkan perilaku yang sama saat membatalkan edit yang dirty.
- Ganti listener per tombol pada list bahan, overhead, dan resep dengan satu delegated handler pada parent.
- Pastikan handler delete memakai salinan/filter array dan tidak bergantung pada indeks iterasi.
- Hapus listener parent lama sebelum memasang listener baru agar render berulang tidak menumpuk handler.

### 4. Inventory hilang dan onboarding

- Di `hppIngredients.js`, turunkan status missing dari inventory setiap render; jangan memfilter atau mengubah array.
- Tampilkan badge/peringatan yang menyatakan inventory tidak ditemukan dan bahwa data snapshot tetap dipakai.
- Sediakan aksi eksplisit **Ganti bahan** dan **Hapus**.
- Alur **Ganti bahan** harus memakai form inventory yang ada, mengikat ulang `inventoryId`, nama, harga, nested units, dan kalkulasi ke item baru tanpa membuat duplikat.
- Izinkan edit snapshot yang masih aman; validasi stok hanya dilakukan ketika referensi inventory tersedia.
- Ubah `toggleOnboardingVisibility()` agar onboarding hanya muncul jika inventory kosong **dan** tidak ada draft HPP. Draft/daftar bahan tetap dapat dibuka saat inventory kosong.
- Pastikan inventory update/cross-tab refresh tidak menghapus referensi yang missing.

### 5. Validasi dan mesin hitung

- Validasi sebelum add/save untuk:
  - nama produk dan nama overhead;
  - jumlah produksi finite dan `> 0`, termasuk desimal;
  - jumlah bahan finite dan `> 0`;
  - jam kerja, upah, dan kemasan finite serta `>= 0`;
  - biaya overhead finite, `> 0`, dan berada dalam batas aman yang sama dengan UI;
  - margin finite dan tidak melebihi 99.
- Perbaiki `calculateValues()` agar tidak menghasilkan `NaN`/`Infinity` dan tidak silent-clamp input invalid.
- Ubah slider margin di `hppApp.js` menjadi maksimum 99 dan perbarui label.
- Tampilkan alert spesifik untuk setiap kegagalan; jangan silent return.
- Escaping semua interpolasi nama user/inventory pada template HPP.

### 6. Race add dan reset

- Tambahkan single-flight guard pada `addIngredientFromInventory()` dan `addOverhead()` dengan `try/finally`; tolak trigger kedua, bukan mengantrikan duplikasi.
- Kosongkan input hanya setelah operasi berhasil.
- Perbaiki `resetForm()`:
  - hapus panggilan ke `cancelEditOverhead()` yang tidak ada;
  - bersihkan state edit sebelum render;
  - jangan menyimpan session kosong setelah `clearHppSession()`;
  - jangan reload halaman;
  - kembalikan UI ke step 1 dan tampilkan onboarding hanya jika memang tidak ada draft.
- Setelah `saveCurrentRecipe()` berhasil, panggil auto-clear tersebut tanpa konfirmasi.
- Jika menambahkan tombol reset manual, buat wrapper async destruktif terpisah; jangan memakai jalur auto-clear.

### 7. Resep dan batas Produksi

- Simpan jumlah produksi desimal dan normalisasi semua field numerik resep.
- Gunakan ID recipe terpusat untuk resep baru.
- Perbaiki lookup/edit/duplicate/delete agar menerima ID string atau numerik lama.
- Jika resep yang sedang diedit dihapus, bersihkan `editingRecipeId`.
- Ubah input quantity Produksi menjadi `step="0.01"` atau `step="any"` dan validasi finite positif.
- Pertahankan field `calculationQty`, `calculationUnit`, `inputQty`, dan `inputUnit` agar logika pengurangan stok Produksi tetap kompatibel.
- Jangan mengubah alur konfirmasi atau atomic rollback Produksi.

## Acceptance Criteria

- Dirty edit bahan/overhead tidak hilang saat berpindah item atau membatalkan edit.
- Delete beberapa item dinamis tidak ada yang terlewat dan listener tidak mengganda.
- Input invalid tidak mengubah state dan selalu memberi pesan yang sesuai.
- Klik dan Enter yang cepat hanya menambah satu bahan.
- Jumlah produksi `2.5` tidak berubah menjadi `2` saat disimpan, direstore, atau diproduksi.
- Slider tidak dapat memilih 100%; hasil HPP/harga jual tidak pernah `Infinity`.
- Inventory yang dihapus tidak menghapus bahan dari draft/resep; peringatan tetap muncul dan aksi ganti/hapus bekerja.
- Draft tetap dapat dibuka saat inventory kosong.
- Simpan resep berhasil, resep tersimpan, lalu form kosong tanpa dialog atau reload.
- Resep dan inventory ID numerik lama tetap dapat dibuka, diedit, diduplikasi, dihapus, dan diproduksi.
- HPP tidak menulis perubahan stok; Produksi tetap mengurangi stok hanya setelah konfirmasi.
